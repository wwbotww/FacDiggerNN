# 每日生产运维

适用于固定 ModelRelease 的真实日频无标签推理。外部契约与缺分消费行为见
[HeyBoss 交接](HeyBoss因子联调交接.md)，826 固定资产与末次验收见
[运行交接](826每日生产运行交接.md)。本页是通用操作规则，不是实时服务状态。

**单一生产者是基本前提**：正常运行仅使用 Docker 内的 `production serve`；
不要在旁边增加 launchd、cron、人工 tick 或 signal 写同一生产目录。
本地开发 checkout 不等于已部署版本；命令必须在确认的部署目录和 Compose project 下执行。
下文写操作只用于明确获准的新部署/维护，不因阅读文档自动授权启动服务或交易。

## 1. 一天的事务与截止

| 项目 | 固定语义 |
|---|---|
| 目标日期 D | 统一 XNYS regular session；时间以 America/New_York 解释 |
| 首次尝试 | D 的纽约 19:00，提前收盘也不提前该策略 |
| 重试 | 每 30 分钟；服务轮询默认 60 秒 |
| 截止 | 下一 regular session 实际开盘，不含截止；不放宽到“当天任意时间” |
| 数据修订 | 最近 10 个交易日，必要时补齐 source 至 D 的缺口 |
| 模型 | 配置显式固定 release ID，不自动发现或升级 |
| 因子 | 只交付 D；不回退旧日分数，不补发过期日冒充当前 |
| 训练资产 | 每日任务永不修改训练 snapshot、bronze 或已发布 release |
| 保留 | source 当前/上一修订；推理最近 10 个 session、每天最近 2 次尝试；FactorBatch 长期保留 |

正常过程：

```text
取得唯一生产锁 / 确认 D 与原窗口
 -> 优先查找并恢复唯一合法原交付（FD-04）
 -> 固定并持久化采集前的计算池覆盖基准
 -> fresh 最近修订 + 复权变化的定向热窗口回补
 -> 质量/身份检查，原子切换 source CURRENT
 -> 源与实际窗口/共享市场输入门禁
 -> 为 D 新建无标签 inference snapshot、加载固定 release
 -> 完整可评分横截面评分、交付目标投影、原子发布
 -> ledger 记账、按策略保留源和推理快照
```

源已到 D 并不代表下一次重试可跳过 fresh 请求；仍须重新取得修订。
source_revision 是内部不透明状态 ID，不扫描全历史计算语义哈希。
外部 FactorBatch 与不可变 release/snapshot 的内容校验保持严格。

## 2. 局部缺数、身份变化与质量门禁

允许真实少量缺数，不允许补造 bar、分数、旧因子或猜身份。
来源/窗口不完整的候选保留 false/null，其他股票继续在完整可评分横截面推理，
而不是为十只交付目标提前缩小模型输入。

默认质量配置来自[生产模板](../configs/production/eodhd_daily.example.yaml)：

| 检查 | 默认值 / 要求 |
|---|---|
| inference.minimum_candidate_rows | 完整计算候选至少 100 |
| inference.minimum_eligible_rows | 计算可评分至少 100 |
| quality.max_computational_missing_fraction | 最多 5%，基于采集前已持久化参考，不随重试缩小 |
| quality.max_delivery_unscorable_fraction | 应交付目标最多 20% 不可评分 |
| quality.minimum_delivery_eligible_rows | 至少 3 只；应与消费者组合最低要求一致 |
| Finance 市场输入 | 共享市场观测与历史窗口另行检查 |
| FactorBatch 完整性 | 应交付行不缺失；eligible 分数全部有限；身份唯一、哈希和格式通过 |

“质量 degraded”可以与完整性 100% 同时成立。缺一行、目标身份歧义/过期和模型错误不是
可容忍的 false/null；交付目标不能从分母消失。阈值调整是明确部署决策，不是事故修复捷径。

历史质量隔离及其依据保存在 source manifest，热窗口裁剪后仍继承。
复权回补以证券身份为单位完整替换已验证历史，不按单 ticker 片段覆盖；先检查原始重复/冲突，
再执行规范化，不能先去重把证据抹掉。

当前元数据与 source 的 ISIN 发生变化时，将相关身份连接范围隔离并保存变化证据，
原候选明确不可评分；这不表示新旧证券具有经济继承关系，不自动拼接历史。
如果涉及实际交付目标且无法唯一可靠映射，仍阻断交付；不涉及目标也要计入固定计算参考、
来源质量比例与市场门禁。大范围异常不能按“少数缺数”放行。

## 3. 状态、重试与观察

| ledger 状态 | 含义与处理 |
|---|---|
| waiting_data | 数据尚未就绪，窗口内等待 fresh 重试 |
| running | 正在尝试；异常退出后的恢复仍须取得唯一锁并核查证据 |
| published | 已有唯一合法交付，重复执行不新增交付/请求 |
| expired | 原窗口已过；保留失败根因，不倒填时间或补发 |
| blocked | 契约、身份、损坏或运行错误需审查；服务不因一个 D 永久停止 |

在已确认部署的终端读取：

```bash
docker compose logs --tail 100 facdigger-production
docker compose exec facdigger-production facdigger production status \
  --config /app/configs/production/eodhd_daily.local.yaml
docker compose exec facdigger-production facdigger production health \
  --config /app/configs/production/eodhd_daily.local.yaml
```

若部署用了命名 project，所有 compose 命令必须使用同一 `-p`，例如 826 的 project 为
`facdigger826`。不要从另一个 clone 不带 project 地启动第二套服务。

`health` 检查心跳并附带业务状态；它不是当天批次可调仓的证明。
`status` 的 `latest.quality` 区分 ready/degraded/insufficient，
应同时看 D、attempts、last error、next retry、cutoff 和 delivery ID。
每次尝试日志保留时间/错误/阶段耗时；告警去重不等于根因消失。
导出日志前脱敏，SQLite 活跃账本需要一致性读取/backup，不能只复制 WAL 周边文件当备份。

电脑休眠、Docker/网络停运与数据冲突分别调查：绝对 UTC 窗口不因休眠顺延。
错过窗口如实记为错过，不以重新计时制造合法发布。

## 4. FD-04：发布后记账前退出

两文件目录原子发布与 SQLite 记账不是同一事务。重启时必须**先核对已有交付**，
不能先拉新修订重算另一个分数再发布。

恢复依据包括原 D/固定 release、原 snapshot/源绑定、交付目标、质量记录、完整文件与真实创建时间：

- 唯一合法且原发布时间在窗口内：恢复同一个 delivery ID 的 ledger；
- 即使当前已过截止，也只可补记这份原来按时发布的交付；
- 多个合法候选、损坏、绑定不符、时间不合法：明确阻断；
- staging/tmp、不完整目录、诊断产物和晚发布都不是正式交付；
- 不改原文件、mtime、created_at，不因数据修订另发同日版本。

跨数据修订、退出重启、重复运行、迟到、损坏与歧义回归见
[production recovery 集成测试](../tests/integration/test_production_recovery.py)和
[复盘 §52](复盘/推理与生产.md#case-52)。

## 5. blocked 的受审计恢复

服务恢复运行不代表 ledger 的 blocked 自动重置。先定位根因、完成修复与回归，再明确审批维护；
不直接编辑 SQLite，不删除 attempt/错误/质量参考，不停止其他项目。

操作顺序：

1. 记录精确 D、固定 release 和 `updated_at`，确认仍在原窗口；备份可恢复资产。
2. 停止并确认唯一生产者已退出，保留原部署配置和挂载。
3. 在受验环境、同一配置/挂载下运行如下维护入口。
4. 验证恢复结果，再启动唯一 serve；由它完成 fresh 请求及正式发布。

```bash
uv run facdigger production resume \
  --config configs/production/eodhd_daily.local.yaml \
  --target YYYY-MM-DD \
  --expected-updated-at '从 status 原样取得的 updated_at' \
  --reason '已审查根因与受验修复的简要说明，不含秘密'
```

维护入口本身不 fetch、不评分、不创建新交付；取得锁后先走 FD-04，再核对状态、原窗口、
release/source 和 compare-and-swap，原子记录唯一恢复事件。重复同一恢复请求返回
already_scheduled，不增加事件或延期。已发布不重新排队；无合法原交付的过期 D 不恢复。
不要仅因把配置复制到本地就对另一套账本执行此命令。
实现与验证见[复盘 §57](复盘/推理与生产.md#case-57)。

## 6. 首次部署与数据初始化

新部署先从[模板](../configs/production/eodhd_daily.example.yaml)建立被 Git 忽略的
`configs/production/eodhd_daily.local.yaml`，人工填写：

- release_root 与真实 64 位 release_id，默认零占位不可运行；
- 独立 source/ledger/inference/output 目录及完整交付 profile；
- CPU/线程、资源与质量参数、所有容器内相对路径和宿主挂载；
- 环境变量 token；YAML 不保存秘密。

```bash
uv run facdigger release verify --release artifacts/releases/RELEASE_ID
uv run facdigger production plan --config configs/production/eodhd_daily.local.yaml
```

plan 显示目标日和窗口，不执行生产事务。确认订阅、配额和资产后，二选一初始化：

```bash
# 已验证且身份可安全衔接的历史 bronze：
uv run facdigger production bootstrap --config configs/production/eodhd_daily.local.yaml
# 没有合适 bronze 时另选 live 初始化，不与上一条连续执行：
# uv run facdigger production bootstrap --live --config configs/production/eodhd_daily.local.yaml
```

live 仅对空 store_root 使用当前身份真实历史，按
`context_length + feature_buffer_sessions + max(min_listed_sessions, 20)` 请求，
审计后仅保留热窗口；826 为 784 日请求、532 日保留。
它会大量消耗 bulk 调用额度；初始化可复用 24 小时缓存，正式 daily 仍 fresh。
这不是 PIT 历史证券主表，不用于替代研究输入。非空 store 拒绝覆盖，不改训练资产。
旧只含单日 universe 的 store 不能靠今日成员补历史，应明确新建 store 并初始化。

从确认的部署目录加载 token 后，明确获准才构建/启动：

```bash
set -a
source .env.local
set +a
docker compose build
docker compose up -d
```

[compose.yaml](../compose.yaml)挂载 configs 只读、data/artifacts 可写，四线程，
restart=unless-stopped。Docker 构建排除真实资产和秘密，不把它们烘焙进镜像。
默认 root 面向 macOS bind mount；Linux 若需非 root，先验证 UID/GID，不以全局可写修权限。
训练数据即使在宽挂载内仍不得由每日任务改写；发布前验证与备份记录应覆盖其不变性。

## 7. 部署与联合验收清单

每次部署记录：受验提交、镜像 ID、唯一生产者、配置/挂载、备份/回滚资产、真实业务状态。
不要只写可移动的 latest tag。回滚要考虑 source/ledger 新状态兼容，不能自动切回已知故障代码。

真实 D 验收至少包括：fresh 请求、固定 release、完整计算池、固定覆盖分母、市场输入、
全部交付身份、score/eligible、快照/源哈希、唯一交付、真实发布时间早于截止、阶段耗时；
还应重复只读校验原交付不变和既有历史交付不变。禁止另外起 tick 证明幂等。

把无秘密证据写入部署指定审计目录，更新有日期交接。过期未交付与消费者未接纳都应直说，
不要将 /tmp 历史诊断当正式交付。FacDigger 验收通过后，再交 HeyBoss 独立完成接纳、
持仓保护、执行时点和连续多日验证；本项目不启动交易。
