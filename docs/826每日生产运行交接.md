## FD-04 发布恢复窗口复验（2026-09-21）

本节记录代码修复阶段的隔离验证：该阶段没有重建/重启生产镜像，没有修改真实 ledger、
source、已完成交付或 HeyBoss，也没有采集新真实数据、启动接纳或交易。随后用户明确授权
重新部署，已于同日完成，见下一节。

原根因是只凭 ledger 判断完成。目录原子发布与 SQLite 记账不是同一个事务；两者之间退出
后，如果直接 fresh 重试，数据修订会产生另一份合法但同日冲突的 FactorBatch。现在先扫描
完成交付，并用已持久化的 inference 质量报告绑定原快照，复用现有 loader、release 血缘、
目标/日期身份及完整计算池门禁进行对账。只有唯一合法原交付可补记；不新增外部协议字段。

| 隔离复验场景 | 预期与实测行为 |
|---|---|
| 目录发布后、记账前退出，源 OHLC/修订标识发生变化 | 恢复原 delivery ID；仅首次采集，字节/时间/分数不变 |
| 重复执行、恢复记账时再次退出、重试计时尚未到期 | 不重复采集或评分，不增加 attempts，恢复仍幂等 |
| 子进程在真实 publisher 返回后 `os._exit(73)`，全新解释器重启 | 从真实 SQLite、release、快照和目录恢复；无需 provider 或训练源 |
| 提交前退出，仅留下 `.tmp-factor-batch-*` | 截止前可重新采集尝试；临时目录不会被认领为交付 |
| N 开盘时/开盘后重启 | 只补记原本准时的 D 交付；无完成目录则 expired，不回退给 N |
| 推理跨过截止、交付时间恰好到达/超过截止、早于 19:00 或晚于当前时钟 | 新发布不落完成目录；非法时间的孤立产物 blocked |
| 两份同日交付，包括不同 release | blocked，不挑选“匹配的那一份”掩盖冲突 |
| 文件损坏/缺失/额外文件，release/快照/血缘/日历不匹配 | blocked，保留原文件，不覆盖、不删除证据 |
| 质量证明缺失、交付目标缩小或身份有效期失效 | blocked，不缩小覆盖分母认领旧产物 |
| 已通过容忍门禁的局部缺分批次 | 原缺分股票继续为 `eligible=false, score=null`，恢复不补分、不遗漏行 |
