## 代码检查决定的实现方式

### 1. 市场条件Linear：在现有统计模型上增加一个明确分支

每个期限h保持原公式：

`s_h(i,t) = w_h^T [x(i,t), q(t)] + b_h + sum_k m_k(t) * v_hk^T x(i,t)`。

`x`为14通道的364维统计，`q`为6市场通道的156维统计，基础头仍是520→3；`m`为
同一A期scaler下的当日6个市场值。交互只加`3×6×364=6,552`个参数，总参数8,115，
不加隐藏层、交互偏置、额外dropout或新的归一化。它是状态交互方法对照，也增加了
参数量；即便改善，也不能单凭此归因为某一个市场变量或排除表达容量的贡献。

代码涉及[finance_statistics.py](../../src/facdigger/models/finance_statistics.py)的
`StatisticsKind`、`FinanceStatisticsRanker`，以及
[配置映射](../../src/facdigger/research/finance_experiment_config.py)的`Candidate`与`candidate_settings`。
拟新增候选`statistics_conditional_linear`，不改变原四候选名称、模型参数键或默认构造。
基础头先按原Linear顺序初始化，交互参数直接以零构造，不能先随机初始化再清零而消耗RNG。
epoch0基础权重必须与对应旧Linear逐张量相同，交互为零，前向分数及后续采样RNG配对。

**市场当日值必须核验。**
[MultiScaleStatisticsEncoder.statistics](../../src/facdigger/models/finance_patch_transformer.py)
末尾取的是每通道最后一次已观测值，不保证就是t日；
[FinanceStatisticsDataset](../../src/facdigger/datasets/finance_statistics.py)又将缓存输出标为全观测。
因此不能直接拿`market[:, -6:]`就声称符合原公式。正式启动前逐fold、F/S日期读取原
市场特征表的当日6通道，确认日期唯一、全部observed且有限，并逐日比对缓存末6维。
只有全部通过才复用此切片；缺失或错配应阻止启动，不前填、不缩支持集、不悄悄改为
“最近已知状态”。若真实输入不能满足，先在本记录追加日期和修订理由，再冻结替代方案。
本轮不改写旧缓存，也不为了增加6个值重建全部窗口统计。
未来V入口须在真实V门禁通过后执行相同的当日值核验，不能为此在F/S准备阶段提前读V。

训练器和观察恢复有各自的模型构造路径，必须同步接入：
[train_finance_transformer](../../src/facdigger/training/finance_transformer_engine.py)与
[build_cell_model / validate_checkpoint](../../src/facdigger/research/finance_experiment_state.py)。
将新参数放入原统计模型head参数组，沿用AdamW衰减规则；复用同一日期训练循环、标签
投影、评分和恢复机制。新候选进入既有`diagnostic_model`/`model_type`身份，不向通用
Finance配置塞入默认字段导致旧`model_dump`或protocol hash全部变化，也不放宽旧校验。

### 2. 小学习率：使用现有字段和两个独立计划，不发明训练循环

当前[训练配置](../../src/facdigger/training/finance_transformer_config.py)已经支持LR字段，
每份研究配置绑定一个supervised config，足以表达本轮：

| 拟新增配置文件，实施时创建 | 作用 |
|---|---|
| `configs/research/finance_market_conditional.yaml` | 只声明条件Linear的15个cell，引用原监督配置 |
| `configs/experiments/finance_patch_transformer_scratch_lr03.yaml` | 从原配置派生，仅encoder LR=3e-5、head LR=9e-5；完整展开并验证其余科学字段不变 |
| `configs/research/finance_low_lr.yaml` | 声明原`statistics_mlp_dropout03`、`finance`两个候选，绑定上述小LR配置，共30个cell |

这些文件目前不存在，不将名称当作可运行命令。保持两个独立plan/输出根目录，以研究
身份区分原LR与小LR，不将`finance_lr03`伪装成模型类型；当前runner按候选决定使用
原始窗口还是统计缓存，复用原候选可避免走错数据路径。无需添加任意逐cell参数覆盖框架。

MLP没有encoder参数组，实际只改变head LR；Finance两个组的比例保持不变。
weight_decay仍为原`.01`；AdamW的实际每步收缩也随LR变化，所以这是既定LR策略的
对照，不能严格解释为只改变梯度步长。若后续要匹配有效衰减，须独立登记，不在本轮
偷偷补改weight_decay。新run不得导入原LR的optimizer、scheduler、scaler或已训练权重。

### 3. 复用旧控制与汇总：跨计划比较，不改写旧身份

旧控制科学提交固定为`1e03b5dfb9f9c5849c8e5566e3c8856a1d7aebc5`，plan hash固定为
`6dc59e2b4ca3a654f549ff26c3702e6bd4f698d384f8d3cdc4c63f81825ec21b`。
在**新比较目录**绑定旧60与新45的来源plan、cell、数据/环境身份、history及原生best摘要；
按fold/seed和指定控制显式配对。不追加旧plan，不将旧完成cell登记成新训练，也不把
不同科学commit伪装成同一版本。

复用[统计缓存读取](../../src/facdigger/datasets/finance_statistics.py)的完整哈希及C索引
校验，通过现有`--cache`只读绑定每fold原F/S缓存。新run科学身份不同，不因此失去
缓存复用资格；数据协议、窗口、通道、日期和逐证券C/L才是复用前提。条件Linear另外
执行上文的市场当日值核验。

实现须验证旧四候选的配置序列化、模型初始化、协议摘要与默认数值路径未变，并把
新run的epoch0与旧对应观察权重直接比较。小LR比较全部参数；条件Linear比较基础头
及零交互。代码改变允许项仅限本轮声明的干预和已有工程修复；不能靠跳过Git检查实现
旧run续写。兼容性不能证实时先停止复用，记录原因，不能静默重训控制并替换历史结果。

将正式F/S汇总实现在`research/`，由原研究脚本提供薄入口，沿用既有逐日指标定义。
保留`analyze.py`的历史副本，新汇总代码进入Git；新输出给出逐cell、逐epoch、分段、
配对差、源文件定位和分析commit，能够只读复查旧结果。默认只消费F/S，拒绝缺分后
取交集；不复制一套训练、排序或标签实现。

## 启动前固定的评价与结果判读

原生S选择规则不变，固定FP32观察不重新挑best。主对照为条件Linear−Linear、
MLP .3小LR−MLP .3原LR、Finance小LR−Finance原LR；条件Linear与其他参照的比较
仍包含在原五候选十个两两比较中。报告全部fold/seed，F/S不作新的显著性晋级门槛。

每epoch含epoch0保存完整F/S三期限daily、预测、风格表及权重；沿用当前完整观察
恢复路径，结束前不按效果删轮次。必须同时报告5日Spearman、排序surrogate、原始
收益Pearson、完整目标loss、原生S分数、best/最终epoch、梯度裁剪与AMP跳步数。
曲线比较给出全部cell共同具备的epoch0–6，6轮以后注明实际样本数或逐cell展示，避免
早停后剩余seed的均值被误认为完整五seed曲线。另报原流程各自S-best及最终状态。

| 观察结果 | 可支持的解释与后续 |
|---|---|
| 条件Linear较Linear跨时期改善，且接近复杂模型 | 支持优先研究可解释的状态交互；仍待统一V确认，不能仅凭S宣称状态机制已定因 |
| 只提高F，S不改善或更差 | 新表达能力没有转化为开发增益；保留阴性结果，继续独立目标/结构对照 |
| 小LR提高S而F明显落后，曲线只是变慢 | 只能说明既定十轮策略不同；结合原定30轮对照判断，不能宣称更高拟合上限或已解决泛化 |
| 小LR在相近F拟合水平下仍缓解S退化 | 支持更新路径敏感性的解释；F拟合度对齐只作诊断，不据此重新选checkpoint |
| 收益只出现在个别fold/seed | 继续标注时期/随机性依赖，不扩网格寻找有利子集 |
| 两类干预均无稳健收益 | 降低其解释优先级；按原包继续目标、结构和干净SSL，仍不默认转向full-Train refit |

真实V评价仍按[原包20项静态比较族](2026-10-08_扩展实验包计划.md#6247-评价晋级与失败判读)
整体冻结。原`.001`实践参考、跨fold/seed条件、HAC/非重叠/bootstrap及Holm均保留，
不把本轮三个主对照另当一个更小的显著性比较族。历史开发V已用于设计的限制也保留。

本轮并行实现V评价的明确清单、输入绑定和合成验收：在新比较目录封存所有来源的
原生S-best，不为此写入旧60目录；评价代码身份与源训练身份分别记录。缺少任一原包
候选或未完成选模时拒绝真实V读取，不能把45个新cell完成当成整个包已就绪。
F/S的`plan/prepare/run/summary`不得创建V缓存或读取V标签；V显式入口始终不提供test/
holdout开关。开发和合成测试此入口不等于现在执行真实V评价。
