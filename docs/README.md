稳定技术文档不追加某次作业的时间线。作业进度、精确参数、全量指标和哈希以已有机器产物、
冻结 manifest 与收据为准；实验记录只摘录支持解释的主表和定位，不复制整份运行台账。
当前判断只在概览维护，历史判断和替代理由留在对应实验记录，不另建 STATUS/TODO/ROADMAP 等入口。

## 后续维护规则

按实际行为、协议或结论变化触发更新；不要求每次改代码都修改文档。
完成前的核对和交付说明统一见[贡献指南](../CONTRIBUTING.md#提交与评审)。

| 本次发生了什么 | 更新位置与范围 |
|---|---|
| 仅内部重构、测试补充或文字修正，外部行为未变 | 无需新增状态记录；已有说明受影响时才修正对应段落 |
| CLI、配置、数据契约、兼容性或操作方法变化 | 上表对应的稳定技术文档及直接受影响的示例；精确默认参数仍以代码/配置为准 |
| 新实验或协议调整 | 启动前在对应实验记录写设计并冻结实际计划/配置；通用规则变化才更新实验设计文档，冻结后的改变另记日期和理由 |
| 获得实验结果或修正解释 | 在原实验记录补结果、局限和决策；影响当前判断、证据缺口或优先级时再更新概览；新记录在概览索引登记 |
| 正确性、兼容、恢复、数据边界或研究解释的重要故障 | 更新对应工程复盘与[索引](项目关键问题与修复复盘.md)，保留根因、回归与限制；科学详表仍在实验记录 |
| 普通排队、运行进度、测试执行或常规提交 | 留在机器记录与收据，不追加长期文档；持续操作方法变化按上面的技术文档规则处理 |

1. **实验记录与证据**：按研究问题或对照集合记录名称、日期、状态、假设、对照与改变项、
   固定条件、事前判读、主表、观察、解释、局限及决策；seed/fold/补跑不各建文档。
   阴性结果、失败原因和被替代判断保留；不可核实的事前判读写“当时未记录”。引用共同协议，
   不反复手抄参数；保留代码身份、冻结计划/配置、产物目录、汇总文件及分析脚本和输入定位。
2. **状态只维护一处**：单项实验的执行状态在该记录；概览只维护当前判断与优先级，
   不复制任务进度。包计划保留原设计和各记录链接，仅在包级阶段变化时更新有日期的里程碑。
   科学结论日期绑定证据范围，不因改字或检查链接而刷新；工程完成与因子有效分开表述。
3. **历史与边界**：区分 F/S/V/holdout、旧/修复后协议、原生 S-best/诊断重评分，
   以及观察/已确认原因、曾提出/已确认/已实现/执行完成。归档只补勘误或导航，不维护另一套
   当前状态；不以已见结果改写冻结设计，不移动或改写原始产物、日志及 manifest。
   迁移检查路径、锚点、命令与关键结果，保护已有修改；秘密与生成物不进入文档提交。
4. **规则按需读取**：`AGENTS.md` 只留项目边界与任务入口；通用实现、验证和分支流程在
   `CONTRIBUTING.md`，秘密和外部文件规则在 `SECURITY.md`。新指令对应可检查的项目约束
   或重复失误，写明适用条件和处理方式；合并重复条款，不另建状态入口或多套 agent 指令。
