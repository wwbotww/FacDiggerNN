# 项目关键问题与修复复盘

本页是持续维护的案例索引，整理于 2026-09-28。完整案例按主题拆分，原编号、问题 ID、
根因、权衡、证据和局限保留；不是待办列表，也不替代现行[开发文档](开发文档.md)与
[实验协议](实验设计文档.md)。较早案例的“当前”应按其发生阶段理解。

## 怎样使用

面试先用 30 秒讲清项目目标，再选择一个问题，按“现象 → 根因 → 方案取舍 → 修复 → 验证 → 局限”讲述。
明确区分实际运行故障、工程验证暴露和研究审查发现，不把测试注入伪装成线上事故。
[讲解、STAR 与记录模板](复盘/面试讲解与记录模板.md)保留完整问答及写作示例。

建议优先讲数据身份（§5/28/56）、精确整日梯度与有限内存（§32/37）、恢复与原子性（§52/58）、
或者不填数据的局部缺分处理（§49/53）。选择能解释验证证据的案例，不只背技术名词。

## 新案例怎样落档

触发条件见 [CONTRIBUTING.md](../CONTRIBUTING.md)。在对应主题文件末尾新增案例，分配不重复的原编号，
添加 `case-N` 锚点，并更新本索引；不要为保持同一主题连号而重排历史编号。
旧问题 ID 有历史重复时，引用同时写案例编号，不误把同 ID 的不同修复合并。

每项至少写证据等级、症状、根因、修改位置、方案取舍、实际执行的回归、未覆盖范围。
短期开发清单不进入复盘，关键证据不要只留在聊天记录；不记录 token 或含秘密日志。

部署时点证据单独见 [826 记录](历史归档/826部署与验收记录_2026-09-24_当前可忽略.md)和
[ICF 记录](历史归档/ICF环境调查与验收记录_2026-09-28_当前可忽略.md)。
