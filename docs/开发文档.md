# FacDiggerNN 开发文档

本文解释当前工程结构和内部契约，面向首次接触项目的开发者。安装见[README](../README.md)，
参数与研究判定见[实验设计](实验设计文档.md)，操作见[训练](训练运行与恢复.md)和
[每日生产](每日生产运维.md)。不要把历史计划、测试通过数字或某机器上的资产当成当前环境事实。

## 1. 工程总览

FacDiggerNN 是一个 Python/Typer CLI 包，不是交易系统。包入口由
[pyproject.toml](../pyproject.toml) 的 `facdigger = "facdigger.cli:app"` 定义。
[cli.py](../src/facdigger/cli.py) 只解析参数、调用领域模块、输出结果与退出码。

```text
研究：provider -> 标准表/来源证明 -> 特征/标签/split -> 不可变 snapshot
                                                   -> 训练 -> predictions -> evaluator
                                                                  -> ModelRelease
生产：独立行情热存储 -> 冻结 scaler 的无标签 snapshot -> 共享模型评分 -> 交付投影
                                                                -> FactorBatch
```

| 术语 | 含义 |
|---|---|
| security_id / symbol | 稳定证券身份 / 展示 ticker；ticker 不作为跨系统自动回退 |
| asof_date | 特征与信号的信息截止日，不是发布时间或最早执行日 |
| universe / eligible | 日期候选集合 / 满足对应环节资格；来源、窗口和交付资格不能混为一层 |
| snapshot | 配置与输入内容绑定的不可变数据集，不是一个可覆盖的目录名 |
| predictions | 内部研究预测，含 target/split 等审计信息 |
| ModelRelease | 内部自足模型发布物，绑定权重、配置、scaler、来源及协议 |
| FactorBatch | 外部唯一因子协议，严格五列和两文件目录 |
| engineering research | 工程可信可审计但来源/暴露不足以支持完整正式研究结论 |

当前主线是 Finance Transformer 九阶段配对实验；E0–E3、M6 和它使用共同数据/评价基础设施，
但不同 runner 的决策、恢复与 holdout 能力不能混用。

## 2. 模块职责与复用边界

| 模块（src/facdigger 下） | 职责与边界 |
|---|---|
| data/providers/eodhd/ | API、token、缓存、预算、原始响应、映射、历史/每日修订和供应商质量判断 |
| data/contracts.py、provenance.py | 标准表与 provider-neutral 标准化证明；下游不读取供应商私有审计作判断 |
| data/snapshots.py、inference_snapshots.py | 训练/无标签快照分离，内容身份与不可变发布 |
| data/session_store.py | 有界生产 source、原子 CURRENT、当前/上一修订 |
| features/、labels/ | 价量、rank、市场特征、Train-only 缩放；市场日历标签 |
| datasets/ | 轻量索引、共享 feature store、窗口、mask、完整日期采样 |
| models/ | 基线、PatchTST 迁移、Finance 模型和无标签完整日 forward |
| training/ | 严格模型配置、训练编排、引擎、checkpoint、runtime、run 状态与资源测量 |
| evaluation/ | predictions 契约、覆盖率、中性化可用性、指标、比较与报告 |
| research/ | 复用训练器的 fold 准备/矩阵/健康审计；旧 M6 的统计、冻结与 holdout |
| inference/ | release、run 回放、共享评分、身份投影、单日与年度交付 |
| production/ | 交易时钟、状态机、质量门禁、唯一发布恢复、常驻服务和保留策略 |

API 字段不能散落到模型；模型不能判断 Slurm 队列或 HeyBoss 持仓；
生产 runner 不复制训练器，不重新 fit scaler。
`configs/` 保存具体协议；`tests/unit/` 与 `tests/integration/` 保存回归。
`data/`、`artifacts/`、`.venv/` 是本机资产，不随 clone 分发，不手工改生成文件。

## 3. 标准数据与来源证明

[contracts.py](../src/facdigger/data/contracts.py) 是字段/类型转换、唯一键、有限价格和业务一致性的依据。
供应商可携带附加审计列，但必须先生成标准表；发现不可信数据时明确失败或按已定义质量规则隔离，
不通过伪造价格或放宽契约让样本通过。

### 3.1 `bars_daily.parquet`

主键是 `(security_id, trade_date)`。

| 必需字段 | 含义 |
|---|---|
| `security_id` | 稳定证券标识；优先使用 ISIN |
| `symbol` | 当日展示 ticker |
| `trade_date` | 市场交易日 |
| `open/high/low/close` | 原始 OHLC，必须为正且满足高低价关系 |
| `volume` | 原始成交量，非负 |
| `dollar_volume` | 成交额 |
| `adj_factor` | `adjusted_close / close` |
| `source_revision` | 来源版本 |

EODHD 适配器还会保留 provider symbol、身份质量、来源交易所、证券类型和最终是否退市等审计字段。

### 3.2 `universe_daily.parquet`

主键也是 `(security_id, trade_date)`，但它是完整证券—市场 session 网格，允许没有 bar。

| 必需字段 | 含义 |
|---|---|
| `listed_days` | 从首个有效历史 session 起累计的上市天数 |
| `exchange` | 标准交易所代码 |
| `security_type` | 当前要求为 `common_stock` |
| `is_primary_listing` | 是否主上市 |
| `is_listed` | 当日是否在上市区间 |
| `is_delisted` | 是否为推断退市 session |
| `is_halted` | 上市期间缺少 bar 时的推断停牌 |
| `industry_code` | 点时行业；当前 EOD-only 来源缺失 |
| `float_market_cap` | 点时流通市值；当前 EOD-only 来源缺失 |
| `close`、`adv20_usd` | 当日价格和 trailing 流动性 |
| `eligible` | 是否进入当日研究股票池 |

`eligible=true` 时强制要求：仍上市、未退市、未停牌、主上市、普通股。

### 3.3 `corporate_actions.parquet`

包含：

- `ex_date`；
- `action_type`；
- 价格和成交量因子；
- 现金金额；
- `known_at`；
- `source_revision`。

`known_at` 不能晚于 `ex_date`。

### 3.4 `delistings.parquet`

每只证券最多一行：

- `delist_date`；
- `last_trade_date`；
- `delisting_return` 或 `terminal_value`；
- `known_at`；
- `source_revision`。

历史动态 EODHD 模式会额外写入 `is_imputed`、`imputation_method` 和 `exchange`。当前默认插值为：

| 交易所 | 插值退市收益 |
|---|---:|
| Nasdaq | -55% |
| NYSE | -30% |
| NYSE American | -30% |
| 未知 | -50% |

这些值是工程假设，不是数据供应商观测值。

来源文件使用 [provenance.py](../src/facdigger/data/provenance.py) 的通用标准化证明。
标准表的语法合法不等于质量可靠；`research_ready=false` 会限制研究结论，
不得通过删除来源 manifest 绕过门禁。真实身份变化与错误 alias、ticker 复用必须区分；
历史冲突隔离事实需要持续保存，不能因热窗口缩短而“消失”。

## 4. 特征、索引与快照

### 4.1 一条权威特征路径

[features/pipeline.py](../src/facdigger/features/pipeline.py) 统一训练 fit 和推理 transform。
旧七通道是调整后收盘/跳空/日内 log return、log range、log1p volume 差分、20 日波动与
成交额稳健 z-score。Finance 另有 7 个同日 rank 和 6 个共享市场通道；
精确参数见实验协议，不在这里重复所有模型超参数。

每个通道有 observed mask。网络张量中的零填充只是存储表示，不能被当作真实观测；
scaler、聚合、masked reconstruction 都须遵守 mask。
标签依据市场 session 而非个股 bar 序号；split 同时限制 label_end 和 embargo。
预训练索引 target-free，未来窗口的缺失只改变 mask，不擅自删掉证券末端样本。

### 4.2 训练快照文件

`facdigger dataset build` 创建：

| 文件 | 用途 |
|---|---|
| `features.parquet` | 缩放后的原始通道及 observed mask；新 feature set 还含 7 个 rank 通道 |
| `market_features.parquet` | 仅新 feature set：每日期 6 路共享市场状态及 mask |
| `labels.parquet` | 原始收益、基准、target、标签边界和退市标记 |
| `sample_index.parquet` | 有 target 的 train/valid/test 样本 |
| `sample_metadata.parquet` | 评价所需行业、市值、eligible 等元数据 |
| `inference_index.parquet` | 不含 target 的全部可推理日期 |
| `pretraining_index.parquet` | 仅新 feature set：无 target/split、未来摘要不越过 Train 的 endpoint |
| `scaler.json` | Train-only 缩放参数 |
| `audit.json` | 行数、覆盖、缺失、退市跨越等审计 |
| `manifest.json` | dataset ID、配置和输入哈希 |
| `source_manifest.json` | 数据供应商来源血缘副本 |

相同语义配置和相同输入文件会得到同一个 dataset ID，移动输入路径或输出目录不改变 ID。
配置 `source_manifest` 时，该文件必须包含：

```json
{
  "standardization": {
    "name": "facdigger.standard_parquet",
    "version": 1,
    "status": "passed",
    "research_ready": false,
    "tables": {
      "bars": {"file": "bars_daily.parquet", "sha256": "..."},
      "universe": {"file": "universe_daily.parquet", "sha256": "..."}
    }
  }
}
```

provider 可在同一 manifest 保存自己的详细审计，但下游只消费上述通用字段。

### 4.3 版本与迁移

| 产物 | 现行边界 |
|---|---|
| 新 Finance 训练 snapshot | schema v5，市场表保留全部 feature sessions |
| 旧价量训练 snapshot | schema v4；不要全局搜索替换成 v5 |
| 无标签 inference snapshot | 独立内容身份；新市场日历策略为 all_feature_sessions |
| E1–E3 完整日监督 checkpoint | schema v3；旧 Huber、chunked ranking 或错位 mask 不可混用 |
| Finance 最佳模型 checkpoint | schema v4；与训练 resume 格式分离 |
| E3 reconstruction checkpoint | schema v2，绑定 patchifier_sequence_start_v2 对齐协议 |

内容寻址产物生成后不修改。算法/日历语义变化用新的 snapshot ID；
旧内容可验证/迁移不等于符合新实验要求。完整快照及外置 checksums 支持跨机器迁移；
本机覆盖只改路径定位，不改原 manifest/config/hash。
详细操作与稳定输出路径限制见[训练运行与恢复](训练运行与恢复.md)。

### 4.4 无标签推理快照

独立读取标准 bars/universe、release 特征契约与冻结 scaler，不读取 labels、target、
test membership 或重新拟合。scaler 保留原始字节，避免跨 Windows 换行重序列化破坏绑定。

`delivery_universe` 保留完整候选，最终 eligible 是来源资格与实际可评分窗口的交集。
Finance 还需要真实历史成员构成的 rank/market 特征，不能将今天成员重复到过去。
生产训练快照永不修改；新交易日使用新的推理 snapshot ID，并与训练 dataset ID 分开记录。

## 5. 模型和训练

| 路径 | 主要职责 | 现行定位 |
|---|---|---|
| E0 | LightGBM LambdaRank / MLP 基线；LightGBM 独立进程隔离 OpenMP | 保留的研究对照，不支持 ModelRelease |
| E1 | 随机初始化 PatchTST | 旧对照 |
| E2 | IBM ETTh1 encoder 迁移、冻结/解冻与载入审计 | 旧对照，需来源权重 |
| E3 | 迁移后金融 masked-patch 预训练，再监督排序 | 旧对照 |
| finance-pretrain | Train-only local/market reconstruction + future summary，probe 选 encoder | 当前配对的预训练阶段 |
| finance-transformer | local/market/统计分支 + 完整日 Set Transformer，1/5/20 日排序 | 当前两组监督模型 |

旧迁移路径不能用 `strict=False` 的成功返回代替权重覆盖率、shape allowlist 和指纹检查；
冻结阶段检查参数/缓冲区是否真的保持不变。
新 Finance 路径从结构与任务上改造，不要求 ETTh1 下载。

完整日排序不等于把完整日所有激活同时放上 GPU。CPU 保留日截面，microbatch 编码，
以两遍重放传播精确日损失梯度；Finance 将小型 embedding 留在完整日跨股网络中计算。
共享 `models/finance_scoring.py` 只做无标签 forward，训练、回放和推理复用它。

编排与引擎分开：编排验证输入、建立 run、导出报告；引擎处理采样、梯度、选择和状态恢复。
Finance runtime 是运行控制，不是另一套训练框架；单写者、原子 last.pt、游标/RNG/optimizer
与 best 的一致性见[恢复语义](训练运行与恢复.md#6-恢复语义与格式边界)。
旧 E1–E3 仍按各自已支持的 resume 契约执行。

## 6. 评价与研究编排

[预测契约](../src/facdigger/evaluation/contracts.py)包括：
`security_id, symbol, asof_date, score_raw, score_neutralized, target, split, model_id,
checkpoint_hash, dataset_id, eligible, industry_code, log_float_market_cap`。

一个表只能包含一个 model_id 和 dataset_id，键为 model/security/date；
score_raw 与 target 有限，neutralized 可以因暴露不可用而为空。
覆盖率相对于同一快照/split 的 expected 样本计算，拒绝意外样本和低覆盖；
不把两组各自可用的不同样本直接称为配对比较。

评价统一输出 IC/RankIC、分组收益、换手/成本、分期稳定性和来源限制。
`predict` 独立加载落盘权重，检查绑定并在原 split 比较 score；只生成研究 predictions、
metrics/report，不再生成第二种 factors 格式。

Finance runner 复用两个训练器和同一 fold 准备实现；CPU prepare、资源 admission、
完整矩阵、独立健康审计分工清楚。旧 M6 另有统计决策、freeze、显式 holdout 解封及
截至 validation 末日的 final refit。所有选择隔离与验收细节以[实验设计](实验设计文档.md)为准。

## 7. Release、评分、交付的内部边界

ModelRelease 是自足的内部目录，包含 checkpoint、checkpoint_protocol、resolved_config、
scaler、training_dataset_manifest、source_run_manifest 和自身 manifest。
它绑定真实源码来源、目标/特征协议、文件哈希和原始 predictions 字节。
release ID 不依赖创建时间；原 predictions 不复制到 release，但适配导出会逐字节核对。

E1–E3 和 Finance 使用两个具体模型族 backend；Finance scratch/pretrained 的最佳监督权重
均已完整，不在推理时重新下载初始化 encoder。未知模型即使名称合法也不会自动获得 backend。

| 文件 | 职责 |
|---|---|
| [source.py](../src/facdigger/inference/source.py) | 原训练 run/config/checkpoint 绑定 |
| [releases.py](../src/facdigger/inference/releases.py) | release 创建、加载和完整性验证 |
| [backends.py](../src/facdigger/inference/backends.py) | 模型族配置、严格加载、窗口适配 |
| [scoring.py](../src/facdigger/inference/scoring.py) | 固定 runtime、完整日评分、标准 score 校验 |
| [delivery.py](../src/facdigger/inference/delivery.py) | 目标与有效期映射、交付投影及计数，不改模型输入 |
| [factor_batch.py](../src/facdigger/inference/factor_batch.py) | 唯一外部五列构造、严格校验、原子 publisher |
| [history.py](../src/facdigger/inference/history.py) | 固定模型按年历史回放、计划与分片恢复 |

先给完整可评分计算池打分，再投影实际交付目标。未交付训练股票缺 ISIN 不阻止 release；
目标映射缺失/过期/歧义不允许缩小分母或自动 ticker fallback。
默认要求 clean 来源；显式 `--allow-dirty` 只允许如实记录 dirty，不跳过其他验证。
`data/paths.py` 与 CLI 显式 dataset 覆盖处理跨系统定位，不改原始身份文件。

外部目录、哈希算法、五列类型、source kinds、缺分持仓语义和发布命令统一维护于
[HeyBoss 交接](HeyBoss因子联调交接.md)。FactorBatch 不包含 checkpoint、标签或配置；
消费者不参与特征重算。固定模型全历史回放是 backtest-only，不伪装为当日交易输入。

## 8. 每日生产边界

`production/runner.py` 编排，`calendar.py` 定义窗口，`quality.py` 检查固定覆盖基准，
`state.py` 持久化 ledger，`publication.py` 处理 FD-04 唯一交付恢复，
`recovery.py` 提供显式 blocked 重新排队，`service.py` 负责常驻轮询。
供应商 daily/identity/quarantine 只负责规范化数据；发布层不猜身份或填价格。

source revision 是内部原子状态 ID，不做全历史语义哈希；内容寻址仍用于不可变快照/release/
外部交付。热存储保留历史逐日 universe、修订和隔离事实，不能只保留当日股票池。

局部缺数、源数据质量、模型错误、交付完整性和容器心跳分开处理。
deadline、质量门禁、失败恢复、身份变化和 retention 的完整规则见
[每日生产运维](每日生产运维.md)；不要在开发文档追加逐日状态。
固定 826 路径/末次证据在[运行交接](826每日生产运行交接.md)，本地开发树不等于生产部署树。

## 10. 扩展与排错

### 新供应商、特征和模型

1. 供应商只新增 provider adapter，先输出四张标准表和通用 provenance，补 fake transport、
   重试、预算、身份/质量测试，不在下游增加 provider 名称分支。
2. 特征扩展在 pipeline/窗口中实现，明确 asof 可知性、mask、scaler 和日历；
   考虑 snapshot 内容身份与原产物兼容，训练和无标签推理逐值对照。
3. 模型先证明输出同一日期/证券排序语义，再扩展具体 backend 与 release 必需输入检查；
   测试研究回放、单日、年度历史和消费者契约，不复制 publisher 或生产调度。
4. 风险暴露来自可靠 PIT 源，不能拿当前行业/市值回填历史；评价和正式 readiness 同步扩展。
5. 数据、契约或恢复修改应增加修复前能失败的回归，清理被替代代码，保持一条权威实现路径。

### 常见现象

| 现象 | 首先检查 |
|---|---|
| 新 clone 没数据/模型 | Git 不交付生成资产；迁移完整快照/bronze，或明确授权重新准备 |
| E2/E3 下载失败 | 只有旧迁移模型需要 IBM 来源权重；新 scratch/finance-pretrain 不需要 |
| 中性化结果为空 | 暴露是否真实可用；不能把 null 改 0 或伪造中性化成功 |
| 恢复拒绝 | dataset/protocol/代码、实际 last.pt、run 锁及显式定位，不删除哈希/锁绕过 |
| 容器健康但没有新因子 | 查生产目标 D、ledger、截止和 quality，不只看 Docker |
| HeyBoss 无法接受 | source kind、预期日/release、身份有效期、五列/两文件及哈希，禁止 ticker 猜测 |
