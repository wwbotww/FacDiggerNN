## 2. B1：把计算股票池与监督标签分开

### 2.1 明确两种集合

对原协议已经选定的日期 `t`：

- `C_t`：快照 `inference_index` 中当天 eligible、历史窗口可用的全部股票；不依赖未来标签。
- `L_t`：原 `sample_index` 及内层切分给出的合法监督行，要求 `L_t ⊆ C_t`。
- 模型计算 `scores_all = model(C_t)`；target rank、相关损失、score-scale 正则、
  selection IC、最终指标只使用 `scores_all` 中对应 `L_t` 的行。

只扩展原日期内部的计算股票池，不增加被 purge/embargo 的训练日期，也不放行 test 日期。
标签 mask 只作用于 loss/指标投影，不能用作 attention padding mask。

### 2.2 数据与接口改动

| 文件 / 入口 | 具体修改 |
|---|---|
| `datasets/window.py` | 为 `SnapshotInferenceWindowDataset`、`FinanceTransformerInferenceWindowDataset` 透传已有 `feature_store` / `market_store` 能力；原始 DataFrame 与 store 互斥，旧生产调用不变 |
| `datasets/index.py` | 新增 `align_labelled_samples(computational_rows, labelled_rows)`，按 `(security_id, asof_date)` 对齐，返回原标签行及内存列 `_computational_row` |
| `training/common.py` | 按 manifest 读取指定日期的完整 `inference_index`；只投影无标签身份和窗口列，不按监督证券过滤 |
| `training/finance_transformer.py` | 使用 B2 计划给出的 train_fit / inner_selection；分别加载对应日期的完整计算行，按计算行加载行情，共享 feature stores；评价 split 同样处理 |
| `training/finance_transformer_engine.py` | `train_finance_transformer` 显式接收 `train_labelled_rows`、`valid_labelled_rows`；selection 和 benchmark 也显式接收标签支持集 |
| `models/finance_scoring.py` | 保持无标签评分 API；按计算行返回分数，标签投影由调用方处理 |
| `training/finance_benchmark.py` | 与正式训练复用同一索引装配/对齐规则，不能继续在较小的标签池测准入 |

对齐检查包括：两端业务键唯一且非空、sample_id 与业务键对应一致、标签行全部存在于计算行、
同键窗口边界和身份一致、`feature_end == asof_date`。不能用 inner join 静默丢样本，
也不能依靠数组长度/行序相同代替按键检查。映射针对 dataset 的实际规范行序生成。

`FinanceTransformerWindowDataset` 继续服务预训练 linear probe，其有标签行语义不变。
不向无标签 dataset 填 NaN/零目标，也不扩大 probe 样本来迁就监督训练接口。

### 2.3 损失与梯度回放

引擎维护 `target_rank_lookup[M,H]`（只有真实标签），以及
`row_to_label_index[N]`（无标签计算行记为 `-1`）。完整日 batch 的逻辑是：

```python
label_ids = row_to_label_index[batch_sample_indices]
label_mask = label_ids >= 0
scores_all = model.score_date(local_leaf_all, market_leaf).scores
loss = existing_multi_horizon_loss(
    scores_all[label_mask], target_rank_lookup[label_ids[label_mask]], ...
)
```

必须先 mask 再索引，不能让 `-1` 取到最后一条标签。沿用现有逐日 average-tie target rank；
最小横截面数量按 `L_t` 检查，不能因 `C_t` 足够大就容许有效标签不足。
scale 正则也只用 `L_t`，避免额外给无标签股票增加直接目标。

`backward_complete_date_with_embedding_replay` 第一遍编码全部 `C_t`，对 loss 反传后保存
全部 local embedding 梯度，第二遍重放全部计算股票和 market encoder。
无标签股票通过 attention 影响有标签股票，可能具有非零梯度；不能 detach、置零或漏掉其 replay。
沿用既有 AMP、GradScaler、RNG 恢复、裁剪和日期累积机制。

### 2.4 评价与审计

selection / 最终评价先全池前向，再按标签键投影。现有 predictions schema、监督支持集、
coverage 分母、selection score_std 的支持集保持不变。
报告分别记录 `computational_rows`、`labelled_rows`、`context_only_rows`、受影响日期数；
已有监督行数字段保持标签行含义，不悄悄改成计算行数。

新实验的历史回放也采用完整计算池并按键投影，详见第 5 节的旧产物兼容规则。

## 3. B2：隔离 SSL、probe 与监督选择，并冻结共享 scaler

### 3.1 划分算法

记 `T = sample_index[split == train]`。`label_end` 是所有监督 horizon 的最晚结束日期，
需要断言各 `label_end_h <= label_end`。采用下列唯一算法：

| 集合 / 边界 | 定义与用途 |
|---|---|
| `S`：监督选择集 | 保持现有算法：T 的最后 `ceil(日期数 × 0.15)` 个日期及原合法数量约束；首日为 `S_start` |
| `F`：监督拟合集 | `T[label_end < S_start]`，逐行保留原 purge；scratch / pretrained 都在 F 拟合、S 选优 |
| `P`：预训练 encoder 选择集 | 从已 purge 的 F 取最后 20 个日期；首日为 `P_start`。保留 F 的实际行，不从 T 按日期补回非法行 |
| `A_end`：SSL / scaler 截止日 | 完整市场日历中 `P_start` 之前的最后交易日 |
| SSL 样本 | 无标签预训练索引中 `future_end <= A_end` 的全部合法行；local 与 market 同边界 |
| probe head 拟合集 | 先逐行筛 `T[label_end < P_start]`，再取该候选集最后 60 个日期；仍只保留筛后的行 |

SSL 必须满足 `feature_end == asof_date < future_start <= future_end <= A_end`，
其历史重建和未来摘要均不能进入 P/S。probe 保持现有 local encoder + 线性 head + 5 日目标定义。
P 用于选择预训练 encoder，随后允许进入监督拟合 F；监督选模仍由独立的 S 完成。

P/S 的 512 日预测输入可以回看更早历史，不额外机械 purge 512 个交易日。
需要阻断的是选择期数据进入被选择模型的参数拟合和 scaler 拟合。
本批不做 SSL 在 A∪P 重训，也不做监督模型 full-Train refit。

### 3.2 必须重建快照，不能只过滤训练索引

当前 `data/snapshots.py` 在内层划分前按整个 outer Train 拟合 scaler。
已保存特征经过 winsorize，不能靠反变换恢复原始值后重新拟合。因此使用已有标准 Parquet
重新生成快照，**无需为本修复重新下载 EODHD**。

新 Finance 快照的构建顺序：

1. 读取标准数据，生成 raw local / market features、labels 和原外层 split。
2. 在 raw features 的日期/可用性上构建 `sample_index`，计算上述 F/S/P/A 计划。
3. 使用 `train_end=A_end` 拟合 local 与 market scaler；所有阶段只 apply 同一套 frozen scaler。
4. 保存原外层 `sample_index` 和完整 target-free `inference_index`；预训练索引构建截止改为 A_end。
5. 新增 `finance_selection_plan.json`，由 manifest 的 artifacts 引用；保留全市场日历。

预训练、probe、scratch、pretrained、后续评价使用同一 snapshot 和同一 scaler，避免迁移
encoder 时输入尺度改变。保持现有预训练导入的 same-dataset 要求。
构建时复用 raw tables，及时释放，不创建多份全量行情副本；峰值内存须重新测量。

plan 记录参数、A_end、P/S 首末日、各阶段日期/行数、purge 行数、最大 label/future end、
local/market scaler fit_end、外层评价行参与拟合数量（必须为 0）。
不重复持久化 F/S/probe 样本表；加载时由同一纯函数重建并核对计划。

### 3.3 唯一配置来源与模块归属

`data/config.py` 的 `DatasetBuildConfig` 增加可选 `finance_selection`：

finance_selection:
  supervised_selection_fraction: 0.15
  probe_fit_dates: 60
  probe_selection_dates: 20

仅允许 Finance feature set 使用；future_horizon 保持 5，其他数值采用严格范围检查。

现有 experiment 的 `selection_fraction`、probe fit/selection dates、future_horizon 保留为
**期望值断言**；任何不一致在训练前失败，不能覆盖 snapshot 计划或另切一套索引。

将 `training/common.py:split_supervised_training_index` 原实现移到 `datasets/splits.py`，
迁移调用方，保持 E0–E3 行为；同文件新增 Finance 纯切分函数。
snapshot 不能反向导入 training.common，后者已依赖 snapshots，会形成循环。

CPU prepare 先核验 dataset 与 experiments 的声明一致，prebuilt 路径仍须核验语义配置、

### 3.4 数据身份

新增非空配置参与现有内容寻址，自然生成新 dataset_id，**不增加通用版本系统或额外 schema bump**。
`finance_selection=None` 时从语义配置明确省略此 key；builder 与 prebuilt 比较共用该规则，
避免改变 E0–E3 和旧 Finance 快照的身份。不要对全部字段贸然使用 `exclude_none`。

修正后的 Finance 训练/预训练/benchmark 强制要求匹配 plan 与 A-scaler。
旧无 plan 快照仍可供既有生产/权重读取；原协议续训使用原固定版本。
监督日期/update 预算不变；SSL 合法日期减少导致每 epoch update 数减少，按真实样本重新计算
scheduler 与资源估计，不复用旧 update 游标。

## 4. B3：让报告数字与判定表达同一问题

### 4.1 Finance 主指标使用日期等权

修改 `research/transformer_runner.py:_paired_result`：保留逐 fold 预测键/target 相等检查，
配对后显式按日期排序；空配对或跨 fold 日期重复明确失败。
只调用一次 `panel_mean_inference`，主字段 `paired_mean_rank_ic_delta` 和对应 gate
直接使用该次结果的 `hac.mean`。三 fold 等权可以保留为明确命名的次级描述，不驱动主判定。

`TransformerComparisonDecision` 增加固定语义 `paired_mean_weighting: equal_date`，
参与已有 config_hash；不新增历史 fold 等权聚合执行分支。
报告写清单位为逐日 paired Rank IC delta，fold 边界不计算跨段自协方差，
`null_mean=config.decisions.minimum_paired_mean_rank_ic_delta`（模板默认 0.001）、
单侧 greater、alpha=0.05。保留各 fold 结果，并给出年度描述。

保持现有 effect floor、至少两个正 fold、两组最差 fold 为正等规则，
明确 `acceptance.kind=screening`、`significance_is_hard_gate=false`。
本批不把 HAC p 值新增为 Finance 硬门禁，也不将 screening go 称为统计确认。

### 4.2 非重叠统计量使用同一原假设

`research/statistics.py:non_overlapping_mean_inference` 增加
`null_mean=0.0, alpha=0.05`，使用 `t=(mean-null_mean)/SE`。
`panel_mean_inference` 的正常/空分支均传递这两个参数，报告记录原假设和推断元数据。
沿用现有 stride/offset、每 fold 重新抽样、`ddof=1` 标准误和近似推断方法；
保留空、单样本、零方差的既有 mean/SE/t 返回语义，包括零方差时 SE=0、t 不可估计，
不为复用推断辅助函数另加 variance floor 或改变旧值，不制造 p=0。
不增加新的非重叠显著性 gate，不把每 5 日抽样宣称为已证明独立。

### 4.3 M6 成功比例按整数判定

将研究配置的 `minimum_positive_cell_ratio` 显式迁移为：

```yaml
minimum_positive_cell_ratio:
  numerator: 2
  denominator: 3
```

`research/config.py` 校验严格整数及 `0 <= numerator <= denominator, denominator >= 1`。
`research/aggregate.py` 的 attribution 和 overall 两处使用同一整数规则：

```text
positive_count × denominator >= cell_count × numerator
required_count = ceil(cell_count × numerator / denominator)  # 用整数运算
```

报告保留浮点 ratio 描述，新增实际/要求成功数及分子分母。6/9 对 2/3 通过，5/9 失败；
显式配置 7/10 时 6/9 必须失败。不用 epsilon/isclose，也不猜测小数代表哪一个分数。
旧浮点研究配置给出明确迁移提示；更新仓库可执行模板，保留历史 run 的 resolved config 原字节。
此配置迁移只影响 M6 研究编排，不改变 E0–E3 训练和生产接口。
既有 HAC/Holm、holdout 门禁保持；历史 no_go 不被重写。

## 5. 兼容、恢复与资源准入

### 5.1 同一份训练语义贯穿所有入口

仅检查 config_hash 不足：B1 改变了相同配置下的计算集合，complete-run 和 matrix 已完成
stage 又可能绕过 engine 的 resume 检查。因此引入一份限定于 Finance 的 `data_protocol`
描述，复用现有 manifest/checkpoint/protocol_hash，不建立版本注册表或额外哈希链：

- 现有 dataset_id、计划参数和确定的 A/P/S 边界、实际 feature scaler SHA-256；
- 监督阶段：`computational_universe=target_free_inference_index`，标签支持为原共同有效 horizon 行；
- SSL 阶段：无标签预训练索引截止于 P 之前，probe 支持由同一计划给出。

run、checkpoint 和 encoder payload 保存相应描述；现有 `protocol_hash` 改为绑定
`{config, data_protocol}`。scaler 哈希用于外部 encoder/模型交接，计划不再另建一串哈希。
导入 encoder 时比较共享 dataset/scaler/selection 绑定，不误比较两阶段不同的 universe 字段。
通道、窗口、encoder contract 和权重 shape 的原有检查继续保留。
描述按规范 JSON 日期/参数生成；核验真实索引的 future_end、P 早于 S 的顺序及 scaler 内的
local/market fit_end，不接受仅声明合规但实际输入不合规的计划。

`training_run` 目前仅有两个 Finance 调用方：增加必需的
`data_protocol_loader(dataset_path, dataset_manifest) -> dict` 参数，
在 runtime 完成 dataset 重定位后、complete 返回或持久写入 attempt/manifest/progress 之前执行。
两个调用方传入同一 plan 核验逻辑及各自实验期望值；研究已完成 stage、发现旧 child run、
已完成矩阵重入也先检查预期协议。失败不把旧 manifest 改成 failed、不增加 attempt，
不写入旧 progress；将当前会提前写日志的 input_validation 观测延后至校验成功，
目录创建和进程锁的获取/释放仍保留。
engine 恢复继续二次检查 dataset/protocol，然后才加载 optimizer、scheduler、AMP、RNG 和游标。

benchmark 报告增加相同数据语义及计算/标签行数。research admission 同时校验新语义、
最大 fold dataset、配置与硬件/资源预算。旧报告只能作为历史性能参考，不能给新训练放行。

| T3 | `C=L`、最小标签数量、额外无标签行 | 相同已缩放输入下与旧公式一致；正则/target rank/最低数量仍只按标签支持计算 |

| T9 | 旧 resume/complete run/child stage/矩阵/准入报告 | 新语义下失败且旧产物字节不变；新协议完成重入只读。测试包括不进入 engine 的早返回路径 |

## 8. 确认后的执行与停止点

确认本方案后按以下范围推进，不直接启动九阶段正式效果实验：

1. 在隔离开发分支实施并完成本地测试；同步职责文档和关键修复复盘。
2. 使用现有标准源表在新目录构建最大 fold（wf3）的新快照，输出计划、行数和 scaler 审计；
   使用现有单快照 `dataset build` 入口及显式绑定 wf3 split 的配置，学校 CPU 作业建议
   64 GiB，并使用合法时限。完整 matrix 的 prepare 仍要求三 folds；不为本次单 fold 验证
   放宽配置或把不完整 runtime 宣称可跑矩阵。已完成不可变快照可校验复用，未完成快照
   仍需重建，不声称具备 fold 内 checkpoint。
3. 固定已验证源码与新配置，在独立 GPU allocation 上重新运行至少 100 optimizer updates
   的准入基准，并执行小型 CUDA/FP16 完整计算池、两引擎中断恢复用例。
   记录实际设备、RAM/显存、耗时、计算/标签行数及恢复误差；旧准入报告不复用。
4. 输出第一批验收报告和新的正式实验入口，保留全部旧结果、旧作业及每日生产配置。
   出现数据/内存/数值失败则保留证据修复，不能删股票、缩窗口、改 epoch 上限伪装通过。

本次确认的执行范围是代码修复、回归测试、一个真实最大 fold 的准备和有限 GPU 工程验证。
不包含真实完整 epoch/九阶段研究矩阵、模型发布、holdout 解封或新的付费数据下载。
100-update 基准不能证明完整 probe/selection/finalization 的峰值、完整 epoch、跨节点、
自动重排队或 24 小时稳定性；这些仍是下一轮长运行验收。CPU/CUDA 小型全流程测试也不能
替代真实规模全阶段测量，验收报告必须逐项区分。

第一批完成后，下一步先在干净选择边界上设计“选预算 → 冻结预算 → full-Train refit”，
解决历史模型过旧的问题，再进行同支持集基线与少量可归因消融；不把本批重新统计带来的
数字变化当成模型改善。
