# 训练运行与恢复

适用于本地、WSL2、普通服务器和批处理集群；当前长训练入口是 Finance Transformer。
实验参数与验收见[实验设计](实验设计文档.md)，架构见[开发文档](开发文档.md)。
平台差异分别见 [Windows](RTX2070_Windows训练指南.md) 和 [ICF](../configs/deployment/icf/README.md)。
以下命令是操作示例，不表示本文整理时执行了采集或训练；占位路径须换成实际资产。

## 1. 先分开源码、输入、输出和生产

固定审阅后的完整仓库、配置和锁定环境，不单独复制 training 子目录，不复制 macOS 的 venv。
研究资产与生产 CURRENT、ledger、行情 store、FactorBatch 根目录隔离；新训练不自动晋级模型。

| 路径/身份 | 规则 |
|---|---|
| 源码与实验配置 | 记录精确 commit、真实 dirty 状态；正常恢复使用相同代码和依赖 |
| Bronze | 标准表 + 来源证明，采集与快照准备串行，不能边下载边构建 |
| Snapshot | 内容寻址、不可变；可搬迁，不能修改 manifest/config/hash |
| 输入迁移清单 | 快照外生成、随原始输入传输，用于检出全部文件损坏 |
| Run / encoder / admission 报告 | 已绑定后保持稳定位置，不按 mtime 猜“最新”目录 |
| Runtime | 本次保存/限时/信号/输入定位，不改变模型、数据或优化协议 |

`output_root`、`pretrained_checkpoint` 仍属于严格配置身份；不承诺任意移动整个进行中的
研究输出后自动恢复。跨实现升级、硬件/精度变化须单独验证，不能只因配置哈希相同就认为等价。

## 2. 选择数据准备方式

### 已有完整快照

单模型可离线训练，无需 bronze 或 token。矩阵需全部三个 fold 的完整快照、外置清单，
以及恰好覆盖研究 folds 的 runtime 映射。未提供 fold 映射时，即使可能命中快照缓存，
原构建路径仍需访问 bronze。

在源端生成校验清单，再一起传输：

```bash
uv run facdigger train snapshot-checksums \
  --dataset /srv/facdigger/inputs/snapshot \
  --output /srv/facdigger/inputs/snapshot.checksums.json
```

不能在损坏的目标副本重新生成清单来掩盖差异。迁移 runtime 示例：

```yaml
checkpoint_interval_seconds: 600
max_walltime_seconds: null
shutdown_margin_seconds: 0
handle_signals: false
dataset_overrides: {}
fold_snapshots:
  wf1:
    path: /srv/facdigger/inputs/WF1_DATASET_ID
    checksums: /srv/facdigger/inputs/wf1.checksums.json
  wf2:
    path: /srv/facdigger/inputs/WF2_DATASET_ID
    checksums: /srv/facdigger/inputs/wf2.checksums.json
  wf3:
    path: /srv/facdigger/inputs/WF3_DATASET_ID
    checksums: /srv/facdigger/inputs/wf3.checksums.json
```

替换所有 ID 和路径；runtime 相对路径以 runtime 文件目录解析。
已有 `folds.json` 的矩阵搬迁输入时，还需在 `dataset_overrides` 按真实 dataset ID 配置
`{path, checksums}`。迁移只改变定位，原 ID、manifest 和全部内容仍须匹配。

### 从标准表构建

迁移完整 bronze：bars_daily、universe_daily、corporate_actions、delistings 四张 Parquet，
以及配置要求的来源 manifest；不要只复制价格表。

```bash
uv run facdigger data validate \
  --config configs/datasets/eodhd_historical_liquid_transformer.yaml
uv run facdigger research transformer-plan \
  --config configs/research/finance_transformer_streamlined.yaml
uv run facdigger research transformer-prepare \
  --config configs/research/finance_transformer_streamlined.yaml \
  --output artifacts/prepared/finance-transformer \
  --runtime configs/runtime/reliable.example.yaml
```

prepare 是 CPU-only，不导入 torch；输出 `preparation.json`、`folds.json`、每 fold 外置
checksums 和可直接给 runner 的 `runtime.yaml`。元数据目录不能放进不可变快照。
每完成一个 fold 保存进度；重复执行校验并复用已完成 fold，未完成 fold 重建，
不支持 feature 计算中途恢复。三份 fold 必须来自相同源文件集合。

新 Finance 快照为 v5（保留没有 eligible 股票的市场 session）。旧 complete 的 v4 准备目录
不会自动升级；在新 output 目录重建、切换新映射并重新 benchmark，不重写旧快照。

### 没有数据，需要采集

这一步需 token、配额、磁盘和明确采集授权，不能把文档示例当成已获准在线下载。

```bash
uv run facdigger data eodhd-plan \
  --config configs/data/eodhd_historical_liquid.yaml \
  --reserve-api-calls 10000 --requests-per-minute 300 \
  --output artifacts/download-plan.json
# 审核报告后才执行：
uv run facdigger data ingest \
  --config configs/data/eodhd_historical_liquid.yaml \
  --reserve-api-calls 10000 --requests-per-minute 300
```

plan 会在线查额度、候选和缓存，不下载全部价格；动态 top-1000 不等于只请求 1000 只历史。
显式额度保护是 provider 选项，非跨服务器原子预留；账户查询也消耗 HTTP 限速。
中断后缓存可复用请求，但标准化/聚合仍重做且占 RAM。不要把 API 缓存恢复当作全流程流式恢复。
默认不启用这些选项时保留原 ingest 行为；日常生产不因此自动改用研究下载策略。

## 3. 正式矩阵前的资源准入

在目标 CUDA/FP16 环境、实际最大 fold（wf3）测试；将路径替换为 prepare 输出：

```bash
uv run facdigger train finance-benchmark \
  --supervised-config configs/experiments/finance_patch_transformer_scratch.yaml \
  --pretraining-config configs/experiments/finance_patch_pretrain.yaml \
  --dataset /srv/facdigger/inputs/WF3_DATASET_ID \
  --updates 100 \
  --output artifacts/benchmarks/finance-transformer-rtx2070s.json
```

默认 7.2 GiB GPU / 13 GiB RSS / 14 天，完整含义见[实验资源预算](实验设计文档.md#8-12-周资源预算)。
其他机器可给 benchmark 和 runner 同时传 `--resource-budget /path/to/budget.yaml`；
报告须匹配实验、数据、设备与预算。研究配置中的 `admission_report` 要指向真实报告。

基准未完整测量加载、probe/selection、checkpoint 保存、恢复与最终评价。
另外用短作业演练这些阶段，确认时限余量与稳定路径，不以 update 速度直接保证全生命周期时限。
改变 microbatch、精度或实验路径绑定必须在正式运行前冻结并重测，不在恢复时自动调整。

## 4. 启动、观察和完成审计

通过数据与资源门禁后：

```bash
uv run facdigger research transformer-run \
  --config configs/research/finance_transformer_streamlined.yaml \
  --runtime artifacts/prepared/finance-transformer/runtime.yaml \
  --run-dir artifacts/transformer_comparison/comparison-01
```

runner 按 fold 编排预训练、scratch、pretrained，不复制训练器；先登记唯一子 run 再启动。
直接训练一个模型时：

```bash
uv run facdigger train finance-transformer \
  --config configs/experiments/finance_patch_transformer_scratch.yaml \
  --dataset /srv/facdigger/inputs/snapshot \
  --run-dir /srv/facdigger/runs/scratch-01 \
  --runtime configs/runtime/reliable.example.yaml
```

预训练使用 `train finance-pretrain` 及 `configs/experiments/finance_patch_pretrain.yaml`。
它输出 encoder，不是可直接发布的最终股票评分模型。

观察进度时先从研究 run 的 `matrix.json` 找实际子 run：

```bash
tail -n 20 /srv/facdigger/runs/scratch-01/progress.jsonl
tail -f /srv/facdigger/runs/scratch-01/progress.jsonl
```

`progress.jsonl` 用于观察阶段、日期/update 和 epoch；完成 manifest 的 `training.history` 保存 epoch 统计。
`manifest.json` 表示状态，`checkpoints/last.pt` 才是恢复权威。
日志未刷新或 GPU 利用率低可能是加载、selection/probe 或落盘阶段，不能仅凭它们删锁/重启。
Slurm 日志、MaxRSS 和设备观察另按站点操作；不要在 CUDA 计算节点外启动相同 run 的第二写者。

完成后只读审计，报告写到 run 外：

```bash
uv run facdigger research transformer-audit \
  --run-dir artifacts/transformer_comparison/comparison-01 \
  --output artifacts/reviews/comparison-01-health.json
```

`comparison.json` 的排序 acceptance 与健康审计不是同一门禁；还需人工审阅。
保存完整模型、predictions、metrics、报告、配置、环境、manifest、history 和运行控制记录。

## 5. 中断恢复的操作规则

重复同一命令与 `--run-dir` 即可校验后继续；已 complete 会验证并幂等返回。
原有 `--resume <last.pt>` / `--resume-run <run>` 保留；
显式 resume 已完成单模型 run 仍拒绝，不用 `best.pt` 替代训练断点。

| 发现的状态 | 行为 |
|---|---|
| 子 run complete、matrix 未登记 | 验证绑定及完整产物后复用，不重复训练 |
| paused / failed / 残留 running，有合法 last.pt | 获得单写者锁后恢复已提交进度 |
| 没有可恢复断点 | 明确报告，不找其他目录的“最近权重”冒充 |
| 损坏或数据/协议不符 | 阻断，保留原始证据 |
| 活跃写者占锁 | 拒绝第二个写者，不凭 PID 或旧心跳删除锁 |

CLI 退出码：0 完整完成；75 已持久化可恢复暂停；1 为捕获的运行失败，参数错误由 CLI
另行返回。OOM、数据错误、人为取消不会默认自动续跑。通用核心不调用 Slurm；
学校包装的受限重排队是独立策略。

[Runtime 模板](../configs/runtime/reliable.example.yaml)支持：

| 字段 | 语义 |
|---|---|
| checkpoint_interval_seconds | 默认无 runtime 时为 null；模板为 600，在下一个完整 update 边界保存 |
| max_walltime_seconds / shutdown_margin_seconds | 本次进程预算与退出余量；矩阵各子阶段共用剩余预算 |
| handle_signals | 显式安装停止 handler；默认 false，handler 只设标志 |
| dataset_overrides / fold_snapshots | 显式输入定位与校验，不改变协议 |

例如一小时作业可设置预算 3600、余量 120；实际余量应覆盖最长不可中断操作。
启用周期保存、限时或信号的精确 epoch 内恢复要求 `num_workers=0`；
原未启用控制的 epoch 路径不因此全局禁止多 worker。
SIGKILL 不能处理，SIGTERM 不保证留够时间，周期断点只是兜底。
“间隔 600 秒”不等于最多丢失 600 秒，因为完整 update/落盘仍需完成。

## 6. 恢复语义与格式边界

安全点是完整日期梯度累积组处理完成、optimizer/scaler/scheduler 已处理且梯度清空。
保存模型、优化器、RNG、sampler 已提交游标、AMP、成功 update、阶段、best/early stopping
和 history；消费游标与成功 update 分开，预取不算已完成。

预训练 local → market → probe 分阶段恢复；selection/probe 从阶段入口确定性重跑，
未完成时不提交 best。最终评价中断会重做评价，不额外训练 epoch。
长阶段超过作业时限应调整已验收的作业预算，不能无限重提过短作业。

last.pt 自足并原子替换，先落 checkpoint 后写 manifest，再导出 best；
best 导出中断可由 last 重建。残留 tmp 和截断日志不是恢复依据。
进程退出安全不等于共享文件系统故障/断电零损失；跨 GPU 也不承诺逐 bit 相等。

训练恢复格式与推理格式分离：新监督恢复 contract 为
`finance_patch_transformer_training_resume`，预训练为 `finance_patch_pretrain_progress`；
旧 epoch-only 断点在必要绑定校验后仍可恢复，旧 reader 不能反向读取新恢复格式。
推理使用的 Finance best checkpoint 仍为 schema v4，不能为加游标而放宽 release 校验。

实现与历史 CPU 故障测试见[训练研究复盘](复盘/训练与研究.md)；
学校 2026-09-27 的合成 CUDA 和 srun 信号演练不等于实际抢占、跨节点锁或完整矩阵验证，
完整时点证据见[ICF 记录](历史归档/ICF环境调查与验收记录_2026-09-28_当前可忽略.md)。

## 8. 长时间实验的验收与阶段观测

本节保留 2026-09-30 的审查顺序；已实现的接口见 8.3，现场证据单独归档。

目标是让同一个实验跨多次进程/作业持续推进：正常到时提交进度，突然终止从最近完整断点
恢复，重复失败有明确上限，完成状态能验证全部产物。可以验收进度丢失和恢复开销的范围，
无法承诺计算节点、共享存储及调度器连续多日不故障。

当前已有完整优化器边界恢复、model/optimizer/scheduler/scaler/RNG/sampler 状态、
原子 checkpoint、单写者锁、固定子 run 和已完成产物校验。这些能力继续复用；本轮重点是
补齐完整阶段测量、可观察性和真实故障验收。学校的 allocation 计数、信号和 requeue
修正放在[学校改造与验收记录第 11 节](历史归档/ICF长训练恢复验收记录_2026-09-30_当前可忽略.md)，不进入模型循环。

下表保留实施前审查及验收要求；已实现的记录能力和仍待真实规模验证的边界见 8.3。

| 优先级 | 代码审查确认的现状 | 完善内容与验收 |
|---|---|---|
| P0：完整阶段测量 | [监督引擎](../src/facdigger/training/finance_transformer_engine.py)和[预训练引擎](../src/facdigger/training/finance_pretrain_engine.py)已有更新/保存/epoch 日志，但没有完整的加载、恢复、probe、selection、最终评价计时；100-update 基准不覆盖这些阶段 | 在现有 progress 回调及编排中记录阶段开始/结束、耗时、行数、进度、保存大小和耗时；在最大 fold 测量峰值 RAM/显存。日志不消耗训练 RNG，不改变优化器调用或选择规则 |
| P0：阶段能在作业片段内完成 | probe、selection 从入口 checkpoint 重跑；[监督最终预测与评价](../src/facdigger/training/finance_transformer.py)也没有中途恢复游标 | 先测量完整阶段并选择足够的作业时限。若最长允许片段仍装不下一个阶段，再实现该阶段的细粒度恢复；不能靠反复重提、减少日期或降低覆盖门禁解决 |
| P0：真实保存与恢复验收 | [runtime.py](../src/facdigger/training/runtime.py)已使用临时文件、文件 fsync、原子替换和目录同步；已有写盘中断及 SIGKILL 合成测试 | 在真实模型有 optimizer 状态及 best 副本后测量保存/恢复，覆盖写盘中杀进程、阶段切换、best 导出及最终产物写入中断。旧完整断点可读，未完整提交的结果不能变成 complete |
| P1：能够区分慢与卡住 | `progress.jsonl` 有时间戳及更新事件，但 probe/selection 内部没有持续进度事件；`elapsed_seconds` 是本次进程口径 | 沿用现有日志增加按时间限频的阶段进度；分别展示已提交步数、当前处理游标、最后保存时间和本次/累计耗时。监控读这些状态，不把进程存活或 GPU 占用当成训练推进 |
| P1：存储与长期内存 | checkpoint 含当前恢复状态、最佳状态及本 epoch 的 audit 列表；100-update 的峰值不能代表 epoch 末 | 记录期初/中/末及多个 epoch 的 RSS、显存、checkpoint 字节数和写入耗时，验证清理后无持续增长。测出瓶颈后才优化 audit 聚合或 I/O，保留统计语义和恢复对照 |

P0 在正式矩阵前完成；P1 在启用无人值守续跑前完成。多卡、扩大 batch、改精度、增加 worker
和改网络结构不作为可靠性修复。暂不引入异步 checkpoint、通用任务服务或新的版本管理框架。

### 8.1 用测量确定时间与恢复边界

以完整优化器更新为训练安全边界，额外测量不能中途提交的数据加载、序列化及评价汇总。
至少记录多次观测的最大值；100 次更新的 P95 不能当成所有阶段的最坏耗时。

```text
退出余量 >= 最长不可中断操作 + checkpoint 持久化 + 包装退出/结算 + 运行余量
训练阶段硬杀回退时间约束 = 保存间隔 + 等待安全边界 + 保存耗时（须实测）
阶段可执行条件 = 冷启动/加载/恢复 + 需整体重跑的阶段 + 退出余量 < 单次可用时间
```

第二式不包含 probe/selection/最终评价重跑成本；这些阶段要单独报告。设置 600 秒保存
只能作为初值，不能直接宣称最多损失 10 分钟。正常时限退出应在最近完成的更新边界提交；
硬杀允许回退到上一完整提交，不应跳过尚未提交的样本。

外部包装提供的剩余秒数，还必须扣除“获取预算到创建 `TrainingControl`”之间的时间。
部署层应在训练入口校准预算，不能让依赖导入或子进程启动延后实际停止时间。
通用训练代码继续接收时间值，不查询调度器；学校包装的审查与修复见上述验收记录第 11 节。
训练编排内的数据加载已计入控制器预算，不能和控制器创建前的启动耗时混为一谈。

### 8.2 验收数据和推进顺序

1. 先补阶段计时与进度事件，并验证开启记录前后训练数值状态一致。时间字段不参与数值
   相等断言；model、optimizer、scheduler、scaler、RNG、sampler、选择结果和科学统计
   仍按既有恢复口径比较，不能放宽 replay 容差。
2. 在独立验收 run 使用真实最大 fold、冻结数据和模型配置，先完成一个预训练
   local→market→probe 周期与一个监督 train→selection 周期。用 runtime 控制暂停和续跑，
   不下调实验的 epoch 上限。首个完整单模型 run 再覆盖最终预测、评价和产物验证。
3. 对已提交进度实施正常限时、USR1、SIGTERM、SIGKILL 和写盘故障。小型 fixture
   做完整连续/恢复数值对照，真实规模核验提交游标、恢复时间、资源峰值及阶段推进；
   不能将后者写成未经执行的整套连续数值对照。
4. 验证完成 run 的重复进入只校验并复用产物，未完成 run 不建立第二个子目录。
   损坏 checkpoint、协议或输入不符明确失败，不按修改时间猜测替代文件或静默回退。
5. 通用代码变更通过完整回归，再由学校包装做 allocation 重入演练和持续运行观察。
   最后进入单 fold 配对与完整矩阵；学校验收和正式结果使用各自明确的 run 身份。

模型、输入与配置已有绑定，Git 和环境在每次 attempt 中留档；当前
[run_state.py](../src/facdigger/training/run_state.py)没有强制拒绝所有源码/依赖漂移。
固定版本的长实验应由部署预检核对已验收代码和锁定环境，禁止边运行边更新该 checkout/venv。
不要在本地兼容路径上突然加入“必须和学校机器完全相同”的约束。

验收门禁继续覆盖无 runtime 的旧 CLI、已有 checkpoint、E0–E3、release/推理和每日生产。
可靠性改动不触及生产配置、已晋级 release 或 CURRENT；训练得到的候选模型仍单独离线验收。

### 8.3 已实现：阶段观测和共享时间控制器

两个 finance 训练器复用 [progress.py](../src/facdigger/training/progress.py)，删除原有两份
JSONL 写入实现。现有 `progress.jsonl` 新增阶段开始、进度、完成和中断事件，覆盖输入校验、
数据加载、模型/优化器初始化、断点恢复、train/local/market、selection/probe、best 导出与
重载、最终预测/评价和产物写入；矩阵根目录另记录最终 comparison 阶段。

日志带 `attempt`、`process_id`、UTC 时间、当前阶段耗时及可取得的 RSS/CUDA 内存值。
循环内进度按 60 秒限频，首次推进和 probe 子阶段切换立即记录；probe 区分 fit embeddings、
selection embeddings 和 head fit，预测/selection 按完整日期计数。保存成功事件带实际
checkpoint 字节数、保存耗时及已提交游标；训练阶段另记录本次观察到的最长完整更新耗时，
包含组批/读取及梯度累积，排除前一次 checkpoint 写入。market 首次更新包含批次准备时间。

观测记录不属于恢复状态：`phase_progress` 的游标可以领先于最后一次持久化，恢复仍以
`last.pt` 为准。进程被硬杀可能没有阶段结束事件，日志末行也可能不完整；监控不得用它
替代 checkpoint 校验。阶段耗时属于本次 attempt；父阶段包含内部保存等子阶段，不能
直接把所有事件耗时相加。`*_peak_*` 是进程生命周期峰值，当前 RSS/allocated/reserved
用于观察增长；未知平台信息保留 null，不重置 CUDA 峰值或初始化设备来“补齐”观测。

`run_transformer_comparison` 增加与单模型入口一致的可选 `control` 参数，可共享已经建立的
时间控制器；不提供时保留原行为。通用层没有学校变量、Slurm 查询或新实验配置字段。
checkpoint、模型结构、优化器、RNG、选择规则、旧 CLI 和推理默认调用方式不变。

新增回归在修改前因缺少阶段事件失败；开启记录后，两个训练器的完整 checkpoint 数值状态
与未开启记录的基线逐项一致。恢复、阶段内停止、最终预测重入及完成 run 的只读重入均纳入
回归。完整验证结果见[复盘第 62 项](复盘/训练与研究.md#case-62)；真实大 fold 性能、长期
资源曲线和学校作业链尚未由本轮 CPU 测试代替。源码/环境预检、空间门槛和跨节点验收仍按
学校部署计划推进。

随后固定新代码在学校 GPU 上复验，七项 CUDA/FP16 连续与中断恢复对照全部通过，仍使用
零容差 tensor 比较；最大 fold 已经通过完整训练入口完成真实 USR1 暂停和断点结算。
